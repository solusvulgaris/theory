# 1. Основы AWS и IAM

## Базовые понятия

AWS — набор управляемых облачных сервисов. 
Ресурсы размещаются в регионе. 
Регион состоит из нескольких изолированных Availability Zones (AZ), что позволяет строить отказоустойчивые системы. 
Часть сервисов региональные, часть — глобальные.

Типичная модель стоимости: 
почасовое использование вычислений, 
стоимость хранения за GB-month, 
плата за запросы и передачу данных. 

Цена зависит от региона, класса ресурса, резервирования и free tier. 
Перед созданием ресурсов нужно определить лимиты, срок жизни и способ удаления.

## Shared Responsibility Model

AWS отвечает за безопасность облака: дата-центры, оборудование, базовую инфраструктуру и управляемый слой сервиса. 
Клиент отвечает за безопасность в облаке: IAM, данные, настройки сети, ОС на EC2, 
правила доступа, секреты и шифрование — в зависимости от сервиса.

## IAM

IAM управляет identities и правами:

- user — отдельная identity;
- group — набор пользователей с общими permissions;
- role — временная identity, которую может принять пользователь, EC2, Lambda или другой сервис;
- policy — JSON-документ с `Effect`, `Action`, `Resource` и, при необходимости, `Condition`.

Policy бывает identity-based и resource-based. 
При явном `Deny` доступ запрещается; 
разрешение должно быть найдено для вызывающей identity и ресурса. 
Практический принцип — least privilege: разрешать только нужные действия, ресурсы и условия.

## Практика безопасности

- Для root account включить MFA и не использовать его для повседневной работы.
- Для людей предпочтительны federation/SSO; access keys создавать только при необходимости.
- Для EC2 и Lambda использовать IAM roles, а не встраивать ключи в код.
- Разделять роли для чтения и записи S3, управления EC2 и deployment.
- Проверять CloudTrail, IAM Access Analyzer и журналы CloudWatch.
- Tags помогают распределять стоимость, искать ресурсы и автоматизировать lifecycle; 
  полезны `Project`, `Environment`, `Owner`, `CostCenter`.

## AWS CLI

CLI использует credentials и named profiles. 
Профиль выбирается через `--profile` или переменную окружения. 
Не добавлять credentials в Git, README, AMI или user data. 
Команды должны быть идемпотентными настолько, насколько это возможно; 
перед массовыми операциями проверять `--dry-run` или список ресурсов.
