# 2. Amazon S3

S3 — object storage. 
Данные хранятся как objects в buckets; 
object состоит из key, content и metadata. 
Bucket имеет глобально уникальное имя и принадлежит региону.

## Возможности

- static website hosting для HTML/CSS/JS;
- versioning для восстановления предыдущих версий;
- lifecycle rules для перехода между storage classes и удаления;
- cross-region replication для копирования объектов в другой регион;
- event notifications в Lambda, SNS или SQS;
- encryption at rest (SSE-S3 или SSE-KMS) и TLS при передаче;
- bucket policy, IAM policy, ACL (ACL лучше не использовать без необходимости).

## Доступ и безопасность

По умолчанию bucket/object не должны быть публичными. 
Block Public Access включается, если публичный доступ не является осознанным требованием. 
Bucket policy — resource-based policy; IAM policy — identity-based. 
Для приложения следует выдавать role только с нужными `s3:GetObject`, `s3:PutObject` и т. п., ограничивая ARN bucket и prefix.

## Versioning и replication

Versioning сохраняет версии одного key. 
Удаление объекта при включённом versioning обычно создаёт delete marker, поэтому восстановление возможно. 
Репликация требует versioning на источнике и назначении и IAM role для S3.

## Стоимость и эксплуатация

Выбирать storage class по частоте доступа: Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier-классы. 
Цена складывается из хранения, запросов, retrieval и data transfer. 
Lifecycle policy снижает стоимость, но переходы и восстановление из archive могут быть платными и медленными.

## Полезные CLI-подходы

Использовать `aws s3 ls`, `cp`, `sync` и `aws s3api`. 
Для автоматизации фильтровать JSON-ответы через `--query`, выбирать формат `--output json|table|text`, 
проверять размер и версию объекта. 
Для больших файлов использовать multipart upload.
